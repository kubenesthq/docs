# Prerequisites

KubeNest hosts no control plane for you. The proven starting path is a standalone install: one
clean Ubuntu 24.04 host, no login, no control plane and no hub connection.

## The proven standalone path

The real-host acceptance used:

- a clean Ubuntu 24.04 host;
- SSH access from the machine running the CLI, with passwordless `sudo` on the host;
- a blank storage device supplied with `--storage-device`; and
- normal outbound access to retrieve container images and Helm charts.

It ran `kubenest platform install --standalone --bundle 1.0` with one `--server` and
`--ha single-server`. All thirteen stages passed in 4m56s. The agent became Ready without a
backend URL, bearer token or hub connection, then reconciled a verification `Project` to `Ready`.

The standalone command needs neither `kubenest login` nor a route to a KubeNest control plane or
hub. Stage 12 keeps the installed bundle, profile set, HA tier and storage ownership in the local
ConfigMap `kubenest-system/kubenest-cluster-record`. A standalone cluster is a complete platform,
not a degraded one.

<Callout type="info">
**This is not an air-gapped claim.** The acceptance host had normal egress to retrieve the bundle
components. It proves that a control plane and hub are not prerequisites; it does not prove an
air-gapped installation.
</Callout>

## A separately operated control-plane path

KubeNest does not provide this service. If you operate your own control plane and choose an install
*without* `--standalone`, that separate path has different requirements:

- the machine running the CLI needs HTTPS access to **your** control plane to authenticate and read
  the bundle manifest;
- the installed agent needs persistent outbound WSS access to **your** hub; and
- the control plane needs reachability to the cluster Kubernetes API for its connected-cluster
  operations.

That path is present in the CLI, but it was not exercised by the kn-sf17 real-host acceptance. It
is not a prerequisite for the standalone command above.

## What this page does not establish

The standalone proof did not exercise a public IP, DNS, an HTTPS endpoint, an application
deployment, a backup target or completed backup, a maintenance window, a three-node topology, or
another host size. Those are not presented here as standalone prerequisites.

For the runnable command and its stage-by-stage evidence, see [Quickstart](/quickstart) and
[Install the platform](/install).
