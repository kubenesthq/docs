# Quickstart

One Ubuntu machine, one command, a complete platform. KubeNest does not host a control plane for
you, and the first cluster does not need one: the documented path is a standalone install with no
login and no hub connection.

You need a single Ubuntu 24.04 host with 2 vCPU, 4 GB RAM, 40 GB disk, SSH access and passwordless
sudo. You also need either a pre-created `kubenest-vg` volume group or a blank device you are
willing to give to the installer. The [install guide](/install) covers those choices.

<Steps>

### Install the CLI

```bash filename="terminal"
curl -fsSL https://get.kubenest.io | sh
```

There is no `kubenest login` step. The installer served at `get.kubenest.io` installs the CLI; if
its destination is not writable, follow its printed remedy: `re-run with --install-dir ~/.local/bin`.

### Install the platform

Replace the example address and storage device with your host and a **blank** device. The
`--storage-device` flag is deliberate: the installer refuses a device that already carries data.

```bash filename="terminal"
kubenest platform install \
  --standalone \
  --bundle 1.0 \
  --name demo \
  --ha single-server \
  --server 203.0.113.10 \
  --ssh-user ubuntu \
  --storage-device /dev/nvme1n1
```

```ansi filename="output"
[10/13] kubenest-agent ok
[13/13] verify ok
agent-reconciles: pass (1s)

Installed in 4m56s.
```

The standalone acceptance run used that shape on a clean Ubuntu 24.04 host. All thirteen stages
passed in 4m56s. The agent deployment became Ready, had no backend URL or bearer token, did not
dial a hub, and reconciled a Project to `Ready`. This is a complete platform, not a degraded one.

</Steps>

## What standalone means

The cluster registers with nothing. It has no fleet view and no `kubenest cluster` commands against
a control plane. Instead, stage 12 records the installed bundle, profile set, HA tier and storage
ownership in the cluster's own ConfigMap:
`kubenest-system/kubenest-cluster-record`.

This proof covers the standalone install only. It does not establish a hosted service, a login
flow, a hub connection, an application deployment, or an HTTPS endpoint, so this quickstart does
not present any of those as a completed next step.
