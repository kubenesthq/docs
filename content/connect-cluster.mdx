# Connect an existing cluster

KubeNest does not currently support connecting an existing Kubernetes cluster — EKS, GKE, AKS,
kubeadm, or an already-running k3s — to a control plane.

Do not run `kubenest cluster connect`: that command is not implemented. Creating a manual cluster
record in the console records metadata only; it does not install an operator or mint a credential.

## What works today

To create a **new KubeNest platform** on fresh Ubuntu hosts, use the platform installer:

```bash filename="terminal"
kubenest platform install --help
```

That installer establishes a new K3s platform and deliberately refuses hosts that already run
Kubernetes. It does not connect an existing cluster record. See [Install the platform](/install)
for the supported new-host path.

Existing-cluster connection will be documented here only once the CLI can install the bundle-pinned
agent through a supported transport and verify its real control-plane heartbeat.
